# 战法平台：55线突破回踩

2026-09-14增加可选“讨论版日线”与多周期观察指引，见[新讨论规则修订](ma55-discussion-upgrade.md)。旧参数默认沿用原版，新版需在公共参数保存；历史事件不被改写。

入口：研究与交付 → 战法平台，路径 `/tactics-platform`。支持手动收盘筛选及自动收盘复盘、日报，参数、任务和股池由平台用户共用。只包括沪市600/601/603/605和深市000/001/002/003股票；同时核验证券类型和在市状态，排除ST、停牌及不可评估标的。已入池样本即使之后失效，仍保留在表现统计中。

## 使用与规则

收盘自动流程、B池胜率、DS V4.1 Flash日报、可编辑提示词及历史知识注入见[收盘复盘与日报](tactic-reviews.md)。启用前增量应用迁移015并重启API/worker。

1. 点击“运行收盘筛选”时，按上海时间选择最近已收盘交易日：15:00前使用上一已收盘交易日，15:00起可筛选当日；休市日按真实交易日历回退。跨零点仍可重试上一交易日。页面显示本次数据日期，提交时固定日期上限，排队跨过15:00也不会自动换日。
2. 后台核验真实交易日历、完整主板名单及目标日状态，拉取前复权日K。首次初始化较慢，关闭页面不影响任务。
3. 所有股票处理完成后，使用可用数据识别最近三个交易日内的突破事件并逐日复算回踩/失效。个股缺口记录原因后跳过，其余结果正常发布，状态显示“已完成（跳过缺口）”；页面注明筛选数量、排除数量和缺失股票。缺口股票的旧证据保留在历史中，不刷新信号、不延长观察期，也不作为本次有效候选。
4. 突破日B入池，在B后两个交易日观察，B+2收盘退出有效池。重复点击、回踩和窗口内再次突破均不续期。无需每天点击也会在读取时按到期时间归档。
5. 在“最近筛选结果”和“历史事件”查看过期事件，点击箭头查看冻结窗口的K线、MA5/10/20/55和逐日证据。

突破条件：MA5 > MA10 > MA20；前收盘≤前MA55而本日收盘>本日MA55；阳线实体≥3%；量/此前5根有效K线均量≥1.5。随后两个市场交易日，趋势保持、量≤突破日80%、距MA55在−3%至+1%时标记缩量回踩。均线包含本日，不使用未来价格。已有事件沿用入池参数版本，新的运行使用当前公共参数。

日线规则近似原文尾盘筛选条件，不包含快速下穿、15分钟做T、自动交易或收益回测。

## 实现边界

页面“入池后如何观察”按钮控制指引展开/收起；有 `quant.strategy.manage` 权限的用户可编辑、保存或取消，读取权限用户可查看。默认文字涵盖B+1/B+2观察、人工盘中判断、尾盘复核、失效与纪律、当前功能边界。文字按纯文本展示，独立版本防止多人覆盖，失败保留草稿；修改文字不改变筛选规则。数据库需补齐幂等迁移 `sqls/012-tactic-observation-guide.sql`，已有编辑不会被重复迁移覆盖。

- Next.js页面和 `/api/quant/tactics` 负责交互、同源保护及 `quant.data.read` / `quant.strategy.run` / `quant.strategy.manage` 权限。
- Python `/api/v1/tactics` 通过现有内部管理员令牌保护。Python统一管理行情与战法表的事务，Next.js不直接写这些表，不额外建立Prisma重复模型。
- 独立 `quantpilot_market_data.tactics_worker` 消费PostgreSQL任务，无新增消息队列。单战法只允许一个活动任务；120秒租约、逐股断点、提交前租约校验防止重复发布。
- Baostock在隔离子进程中串行请求，单请求60秒硬截止，超时终止连接，最多额外重试两次。股票间隔0.3秒。逐股保存进度，不把整个扫描放进HTTP连接。
- 单只股票缺失不再阻止发布；重跑会重新获取缺口数据。同一交易日的已校验快照批量复用，只在当前主板名单范围内恢复，不复用以前的缺口记录。名单/交易日历等公共步骤失败，或全部股票都取数失败时，保留旧结果并报告失败（运行日期当天22:00前可每5分钟重试公共步骤）。
- 每只股票先请求120个交易日范围，老股有效K线不足时扩大至一年。同一日期复跑用完整缓存；下一交易日重拉计算窗口并整体替换，避免拼接不同前复权基准。当前没有仅拉一根日K的优化。
- 价格同时进入正式 `stock_bars` 与覆盖状态；战法运算读取自己保存的完整同源窗口，证据使用每次运行不可变的逐股快照。完整目标窗口就绪前不采用通用读模型里的异源拼接数据。

## 本地和部署准备

现有数据库按顺序补齐 `sqls/011-tactics-platform.sql`；新环境可用既有 `npm run db:init`。该迁移只新增表和默认配置，不自动拉取行情。

```bash
npm run worker:tactics
# 或只领取并执行一轮
npm run worker:tactics:once
```

`npm run dev` 在行情服务启用时默认管理战法worker；另有进程管理器时设置 `QUANTPILOT_DEV_MANAGE_TACTICS_WORKER=0`。使用 `npm run dev:web` 或 `next start` 时需另启worker。页面会提示执行器离线。

生产服务模板：`deploy/systemd/quantpilot-tactics-worker.service`，使用与行情服务相同的数据库环境；服务停止会释放任务或由租约超时恢复。需要运行环境已具备uv和Baostock依赖，工作目录和用户应匹配实际服务器。此功能实现不包含生产部署或生产数据迁移。

## 观察池详情行情（2026-09-09）

详情使用共享“K线与量价结构”，支持日线、分时、价格/成交量/成交额联动。日线均线为 MA5/10/20/55/60/233；MA233仅用于观察，不参与筛选。打开详情优先读取图表缓存，无缓存回退事件快照；旧快照成交额仅按证券和日期从本地正式行情补齐，仍缺失明确展示，不估算。新增筛选快照保存源端真实成交额。

先增量执行 `sqls/013-tactic-chart-cache.sql`。GET `/api/v1/tactics/events/{event_id}/chart?mode=daily|session` 只读本地；POST同路径 `{mode}` 显式取数。Next代理沿用 `quant.data.read`、内部令牌、同源保护；证券由事件确定，拒绝客户端覆盖。公共缓存按证券、视图和参数隔离。刷新在单个API实例内合并同证券同视图请求，22秒超时；旧请求不得覆盖较新获取时间的缓存。

日K请求最近320根前复权行情，源多返回时仅保留最近320根，完整替换同源价格窗口。若少于292根，最近60根中可能存在MA233历史不足。金额补充复用现有服务，仅补真实成交额，不拼接价格。分时获取最新可用交易日及上一交易日比较，明确注明交易日期；缺少比较数据时保留缺口说明。盘中日K标注“当日未收盘”，该状态保存在缓存中，防止收盘后把盘中旧缓存误认为完整日K。

刷新成功持久保存完整响应和获取时间，刷新失败保留旧图及原时间；重新打开、跨页面或行情服务重启后仍可读取。原始突破、回踩、到期证据在图表下独立显示评估日期，刷新不改变观察池成员或有效期。不增加自动监控或交易。

验证命令：`node scripts/checks/check-tactic-charts.cjs`（真实有效池刷新及移动端，另拦截失败响应验证旧图保留）；Python测试 `test_tactic_charts.py` 和 `test_tactics_postgres.py` 覆盖合并、超时/空结果、缓存持久化与证据隔离。

## 增量更新与耗时统计（迁移014）

数据准备按同日复用、5交易日重叠核验、完整窗口回退执行。仅Baostock前复权同口径缓存、落后1至3交易日且历史有效K线充足时允许增量；至少2根重叠K线双方有成交，精确核对OHLC/成交量/ST/交易状态，成交额双方有值时也核对。缺数据、字段变化或合并校验失败会重拉完整120交易日窗口，继续沿用不足60根时扩展一年历史的规则。距离最近全量获取20交易日强制全量核对；不声称替代复权因子校验。

迁移014仅新增采集口径与基准日期、逐股采集诊断；旧Baostock缓存基准初始化为原缓存日，不改价格。`QUANTPILOT_TACTICS_INCREMENTAL_ENABLED=1` 默认启用，设为0并重启本地worker恢复完整窗口路径（仍允许同日缓存复用）。保留单连接串行及每只0.3秒等待，未引入并发。

GET运行响应新增可选 `acquisition`：复用、增量成功、全量路径（含回退）、回退数、缺口数、实际请求/行数、取数/校验/持久化调用/缓存读取/等待/准备累计耗时和回退原因。按逐股记录汇总，不累加页面轮询；断点保留已有诊断，重试缺口累加本任务之前已记录耗时，同日从其他任务复用不带入历史取数时间。平均取数以实际取数股票为分母。旧任务显示“暂无耗时统计”。持久化时间不含最终诊断写入及提交；逐股准备不包含名单/日历及最终策略计算，不等于完整任务耗时。
