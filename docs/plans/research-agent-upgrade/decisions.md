## D19 / 2026-10-19 / S08：独立 CPU 解析器及人工质量门

状态：accepted，细化 D03。实际采用独立 Python 3.12 的 Docling + RapidOCR/ONNX CPU 服务，通过 bytes/jobs/v2 回执连接 parser port，不放进 market-data 环境。包和模型 hash 进入指纹；失败、取消和超时回执可重试，成功页缓存保留。OCR/表格结构一律 needs_review，不能直接发布 known 事实；原生文本优先，只有空白、乱码或失败才在 auto 模式触发 OCR。金融规则继续在 TS 应用层。

当前锁定实跑为 Docling 2.140.0、RapidOCR 3.10.0、ONNX 1.31.0、Torch 2.14.1+cpu。Windows 原生和当前 Linux CPU 镜像均完成页定位、真实金额行列 18 项及合成负数/跨页 12 项机器核对，取消/超时可停止自己的模型进程并保留完成页。Docker 配方限制 2 CPU/4 GiB/单槽；E-S08-04 实测禁网 probe / HTTP 峰值约 2.14 / 1.70 GiB、无 OOM，1 秒预算实际 1382 ms 停止且保留第一页，后续冷进程完成两页。最初解包失败及引擎 500/SIGBUS 证据保留，根因未证明；精确回收任务失败构建缓存后当前 no-cache 镜像已构建/验收。CPU 依赖显式指定 PyTorch CPU index，避免拉入 Linux CUDA 包。

原生试点单页约 15—63 秒（早期冷进程有 135.6 秒记录），容器本批约 13—74 秒；据此服务默认 180 秒、平台请求 240 秒。这不改变研究 40 次/20 分钟预算，也不是受控性能对照。按需选择 docling/ocr，跨页表不自动合并。第二页合成表头有“合并”→“合井”误字，原始错误保留；本批人工抽查已由用户逐项确认通过（E-S08-02），新容器单元格/坐标机器对照一致，不自动解除业务资料 needs_review。pip-audit 的 +cpu 包跳过与上游版本补查分别记录，不能声称完整二进制审计。后续先扩充真实中文复杂版面和业务审查样本，再扩大使用范围。
