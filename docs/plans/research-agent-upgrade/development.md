# 财报研究 Agent：开发与交接规范

这些规则服务于 [20 步计划](plan.md)，补充项目已有 [模块边界](../../module-boundaries.md)、[文档规范](../../documentation-style-guide.md)、[评测指南](../../evals-guide.md) 和 [数据生命周期](../../data-lifecycle.md)。用户当前明确指令优先；规则用于减少反复解释，不制造逐步审批流程。

## 工作方式与改动边界

先核对实际工作区，再读进度。2026-10-18 建计划时仓库已有大量未提交工作，公司研究部分文件尚未跟踪；因此不能从单个 HEAD 还原当时系统。

每次会话先登记本步及拟修改文件。默认只保留一个主步骤为 `in_progress`；用户要求并行工作时先明确文件所有权和合同依赖，避免多人同时更新同一状态。已有他人改动必须保留，发现同文件正在变化时先核对，不覆盖、不批量 stash/reset/clean。新建分支按项目约定使用 `codex/` 前缀，不自动把所有未提交文件加入一次提交。

一个步骤可以分多个小补丁；每个补丁解决明确问题。不要把 unrelated 重构、模型迁移或格式化混入功能步骤。新文件按责任拆分，不继续扩张 runtime、contracts 或页面大文件；遵守已有模块边界检查预算。

本次建立计划未授权执行所有开发步骤。后续用户说“继续 Sxx”时，完成该步骤及必要修复、验证和交接；常规技术选择自主推进。超出任务范围的生产操作、对外发送或明显破坏性操作仍按授权处理。

## 模块分工

| 边界 | 负责 | 约束 |
| --- | --- | --- |
| `src/app/company-research/` | 研究工作台、状态控制 hooks、组件组织 | 页面不直接操作数据库或调用模型，不把任务权威状态只放浏览器 |
| `src/app/api/company-research/` | 身份、权限、参数、幂等、调用应用服务与事件投影 | route 保持薄；来源正文、文档下载和事件同样校验资源归属 |
| `src/lib/company-research/` | 研究合同、规划、来源、检索、事实、证据、报告、版本与运行编排 | 金融语义留在应用/领域层；跨模块只走明确接口 |
| `src/lib/agent/` | 通用 PI 循环与治理机制 | 不增加财报列名、证券规则、固定报告主题等业务知识 |
| `services/market-data/` | 已有行情/财务服务与适合复用的确定性计算 | Python 不引用 Next.js 源码；复用而非复制同一指标算法 |
| `services/document-parser/` / parser port | 文本/OCR/表格解析、稳定块和定位 | 独立 Python 3.12 CPU 服务，平台通过版本化合同访问；S08 人工/容器验收状态另记 |
| `src/lib/eval/` 与研究 runner | 通用统计、核验及研究专用样本执行 | 不改已有看板数据含义；新链路单独登记版本和任务分布 |
| `.pi/` | 被发布的研究 Skill 与参考材料 | 沿用 registry/lock、完整性和发布检查；候选在实验目录隔离 |

默认继续使用 Next.js、TypeScript/Zod、现有 Python 服务、PostgreSQL 与 PI。新增数据库、模型、检索服务或 Agent 框架，先给出具体缺口、替代方案和开发集结果，再写决策。Memory 继续管理用户偏好，AKEP 继续管理已发布共享知识；本次文档索引是有作用域和生命周期的研究资料，不形成职责重叠的新共享知识平台。

## 数据、定位与时间

- 记录原文 bytes hash、source ID、文档版本、取得时间、披露时间、报告期、parser/version、页/块/表格定位及所属范围。检索块、引用和报告都必须能反查对应原件。
- 区分 PDF 文件页码与印刷页码。没有定位坐标时返回页码和片段；不推测 bounding box。截断、失败页、OCR 质量和表格未识别要进入资料质量状态。
- 财务事实保留原值、单位、币种、精度、累计/单季、合并/母公司、重述及引用。规范化和比较使用确定性计算；空值、0、未知和不可比较有不同语义。
- 判断可用时间使用已核实披露时点，不拿抓取时间代替。仅有报告期、URL 日期或搜索排序时不足以证明可在历史时点使用。未知日期需要核实或标为不可用于严格历史结论；具体规则在 S02/S04 冻结。
- 新证据不能倒灌旧 asOf 报告。新财报和重述保留独立版本，变化说明应区分业务变化、口径变化和资料修正。
- 原文、索引、报告的权限一致。授权边界由可信服务端身份派生，不能接受模型指定任意 actor/tenant/project。只读检索、文档预览、下载和缓存命中也必须检查作用域。

## Agent 和恢复语义

工具输入输出经 schema 校验；业务工具区分只读、状态修改与外部副作用。应用决定权限和审批，来源正文、搜索结果或 Skill 内容不能授予权限。证据中的指令按资料处理，不能覆盖系统目标或工具政策。

运行上下文保留本次任务/计划版本、问题清单、已核查事实和待解缺口；大量正文放到可检索存储。只记录可观察事件、工具结果、公开进度和用量，不持久化或展示隐藏思维链。

复用 claim、lease、heartbeat、fencing、checkpoint 和幂等机制。恢复是从已提交状态重新规划，不是重放隐藏模型会话。只读外部请求在崩溃边界可能重发；只能对实际保证的数据库提交声称去重，不泛称整个系统 exactly-once。

U 系列的计划图、缺口、预算纯策略和财报调度保留在公司研究层。节点软份额用于让出优先级，父任务原子预算仍是硬限制；准入失败在扣额和工具副作用之前返回。局部 planVersion 不替代请求/计划 revision 或 Worker generation；checkpoint 与局部修订事件必须同事务且受执行权保护。恢复保留变体、缺口尝试、证据增量及累计主循环模型请求数，不能用重写结论或重建 attempt 重开已停止缺口。

计划修订使用 expectedRevision 和幂等键，持久化后才公布新版本。旧执行在安全边界停止，其晚到写入必须失效。修订继承同一逻辑请求累计的成本、工具次数及截止约束；明确的新研究请求才具有新的预算。用户看到“等待变更生效”时不得伪装为已经切换。

当前研究配置默认最多 40 次工具调用、20 分钟，实际以当前 `researchConfig()` 为准。引入 OCR、检索和候选评测后，需要另外记录它们的资源耗用。变更预算必须作为独立实验变量，不能通过提高预算制造算法提升；费用未知不能写成 0。

## 界面与协议

前端组件在应用控制下渲染计划、事实、证据和差异。优先复用本地组件与类型合同。AG-UI 只作为边界适配；A2UI、MCP Apps、通用多 Agent 不自动进入首版范围。

事件至少能定位 task/run、版本与 sequence；重复和乱序可处理，断线后从服务端快照恢复再消费增量。界面离开、切换任务或重连后不能把旧流写入新状态。用户修改先显示待提交/待生效，后端确认后再成为已生效状态。

新增流程覆盖加载、空结果、错误、partial、取消、等待变更、断线和终态。金额表格标单位/期间，引用阅读器展示原文，技术诊断收进详情。使用语义化控件、键盘焦点、移动布局和可访问名称；真实截图用于视觉验收，示意图不充当功能证据。

## 评测合同和质量门

先冻结输入和评分，再优化。S02 记录每项指标的分母、排除规则、四舍五入容差、固定资料和实际样本量。以下是建议初始目标，需在 S02 用版本化合同落实；变更目标要说明业务理由并重建可比较基线，不能在看到候选成绩后放宽标准。

| 指标 | 定义 / 建议门槛 |
| --- | --- |
| 身份、权限、时间、引用完整性 | 已登记硬门用例全部通过；所有被验收报告都不得有已知硬门错误。有限用例通过不等于全场景安全保证 |
| 关键数值正确率 | 与人工规范化答案及预声明容差匹配的必需数值 / 全部必需数值；缺失也计入分母；建议至少 95% |
| 结论证据支持率 | 人工或经校准独立 judge 判为被证据支持的实质结论 / 全部实质结论；建议至少 90%，同时检查必需问题覆盖以防少答刷分 |
| 任务完成率 | 完成必需问题且所有硬门通过的任务 / 全部有效评测任务；partial/failed/cancelled 不算完成，建议至少 80% |
| 检索质量 | 在固定人工标注下统计 Recall@k 或定位命中率；记录实际 k、标注粒度、过滤条件与开发集基线 |
| 首轮、修复与稳定性 | 首轮完成率、最终完成率、修复次数、重复执行结果分别记录；建议最终选择至少 3 个代表场景各重复 3 次，并受事先确定的总预算约束 |
| 耗时和成本 | 端到端与各阶段耗时、Token、模型/搜索/OCR 成本及失败重试；无收费数据标未知/估计；总耗用除成功交付数，零成功时每成功任务成本不可计算 |

这里的建议值不是已经测得的成绩。保留集小样本需逐题披露数量与不确定性；不能用一个百分比掩盖样本少。只有同题、同资料、同模型/预算/评分及相同能力范围才报告改善幅度。

合同测试、人工抽查、真实模型 E2E、线上用户分布是不同证据。已有 Mutation suite 和 Judge 校准样例不等于新研究链路已被验证。独立评审缺失时如实标明；规则评分与同源模型评分不冒充独立判断。

S19 的优化器只看到开发样本和失败，不能修改评分器或读取保留答案。保留集只在最终候选冻结后用于验收；若其失败被用于下一轮优化，重新划分独立样本并登记，不能继续宣称原集未见。

新增测试覆盖业务风险、边界和失败，不写仅复述实现的测试。低风险纯文案无需新增测试代码。完成适用检查后不无理由重复全量测试。命令的退出码、实际 scope、日期和环境写入进度，未运行要说明原因。

已有检查失败时先保存修改前状态，明确与本次的关系；本次引入的失败应修复。必需验证缺依赖时，状态保持 `in_progress` 或 `blocked`，其他独立工作仍可推进，不宣称 done。

## 证据留存与跨会话承接

每个完成步骤在 `progress.md` 关联一个 `E-Sxx-序号` 证据记录，至少包括日期、工作区身份、文件/版本、实际命令或人工动作、结果、原件位置/hash、已知限制。可读摘要进入 Git，原始敏感样本和大型报告留在受控本地/外部存储。

拟用 `data/research-agent-upgrade/evidence/Sxx/` 保存需长期保留的本地原件，`tmp/` 仅用于可再生临时产物。首次使用证据目录时登记所有者和清理策略；不得覆盖用户资料。测试报告一旦作为通过依据，保留原件或稳定归档副本及 hash。受控外部地址不能包含凭据。

同一 HEAD 上的脏工作区要补充本步文件清单与 hash/可恢复差异；已有未跟踪代码也纳入身份。只保存 hash 不能还原文件，换机器前还要实际保留对应文件或经授权提交。不要复制 `.env`、访问 token、私有题目和原始用户信息到交接记录。

会话结束前按以下顺序写回：

1. 保存改动和必要验证结果，追加 `E-Sxx-*` 证据；不存在的产物不得先写为已完成。
2. 更新本步状态、完成日期/会话标识及依赖影响；重要选型更新 `decisions.md`。
3. 更新当前交接：做了什么、剩什么、下一动作、涉及文件、如何验证、环境和进程、阻塞及未提交状态。
4. 追加本会话的简短历史记录。最终回复与文件状态一致，不只把交接留在聊天里。

遭遇中断且来不及写回时，新会话以源码、可恢复差异和真实报告核对，补录“中断后核实”，不能凭猜测补完成。若源代码变更使已完成步骤验收失效，把该步重新打开并注明受影响的下游步骤；不要删除旧通过记录。

## 文档与交付

研究基础层实跑命令现已登记：`node --import tsx scripts/research/verify-fixtures.ts`、`node --import tsx scripts/research/run-baseline.ts`、`npm run test:research:postgres`。用法分别见 evaluation.md、baseline.md 和公司研究专题；普通单测默认跳过 DB 集成，不能把跳过写成数据库验收通过。

U 系列扩展清单使用 `node --import tsx scripts/research/verify-fixtures.ts --dataset=fixtures/company-research/development-v2.json --output-dir=data/research-agent-upgrade/evidence/U04/<新目录>`；默认无参数用法仍核对旧 v1。v2 检查原件、真实解析回执、原文引用、原值与重述比较的精确复算，并分列机器定位与人工确认。准备数据能算出 million_yuan 不代表生产金额合同支持该单位；未冻结标签和部分扫描不能据此解除真实执行阻塞。人工入口见 [板块 1 核对](block1-review.md)。

改变 API、配置、数据、页面或运行行为时更新对应专题；本目录只保存计划/实施证据，不复制整套现有使用手册。开发文档使用仓库相对路径便于迁移，面向用户回复使用可点击绝对文件路径。

演示与简历只采用实际实现和可复核结果。保留失败原因、样本量、配置和局限。生产部署或数据同步需遵守对应 release/data 规范；S20 的开发验收不自动触发生产操作。
