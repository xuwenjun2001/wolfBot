# 财报研究 Agent：20 步实施计划

计划版本：v1，2026-10-18。产品目标和范围见 [入口](README.md)，开发规范见 [development.md](development.md)，实际状态只在 [progress.md](progress.md) 更新。

每一步是一个有独立验收结果的工作包，可能跨多个会话，不等于一天或一次提交。默认按编号推进；表中的依赖是最低前置条件，只有用户要求批量推进且文件/合同不冲突时才调整顺序。新增发现先记录进度与决策，避免把一个步骤悄悄扩大成另一套平台。

## 阶段和完成标志

| 阶段 | 步骤 | 阶段门 |
| --- | --- | --- |
| A：固定目标与基线 | S01—S05 | 样本、评分、基线、版本合同和持久化边界可复核 |
| B：资料进入证据库 | S06—S10 | 固定财报能解析、定位、规范化并按问题检索 |
| C：Agent 产出可检查结果 | S11—S15 | 一家公司两期财报完成真实研究，界面可看进度、查原文 |
| D：用户干预与交付验收 | S16—S20 | 修订、更新、恢复、对照实验和演示材料形成完整闭环 |

后续文中的新目录、命令和合同名均为拟新增产物；必须在对应步骤实现并登记后才能把它们写成“可运行入口”。当前源码优先入口是 `src/lib/company-research/`，现有命令见开发规范。

## S01：核实当前系统，冻结首版场景

- **依赖：**无。
- **工作与落点：**核对 `company-research` 的 contracts、runtime、tools、connectors、store、页面和 Worker；阅读对应 API、权限、schema、现有测试与 `docs/company-research.md`。记录当前分支、HEAD、相关未提交/未跟踪文件及其 hash，不把 HEAD 当完整工作区快照。
- **交付：**本目录新增 `baseline.md`，列出已有/拟新增能力、真实调用链、启动依赖、三类研究问题、数据与模型配置名称及已知限制。模型凭据只验证是否配置，不记录值。确认研究功能已有的归属/共享范围。
- **验收：**从当前源码能追踪一次创建、执行、取消、交付路径；场景明确为单公司双期财报；关键文件已辨认归属，后续修改不覆盖既有工作。更新进度中的基线身份和决策。

## S02：准备固定资料、人工答案和评测合同

- **依赖：**S01。
- **工作与落点：**为三类研究问题准备合法取得的双期财报、原文定位和人工答案，新增研究专用数据集/评分合同，复用 `src/lib/eval/` 的通用能力。样本包含扫描件、表格、单位不同、不可比较期间、矛盾或缺失证据、晚于截至时间的资料。
- **交付：**本目录新增 `evaluation.md`；登记资料 hash、版本、披露时点、题目和 rubric。首轮建议至少 6 家公司、每家 3 个问题，按 4 家开发 / 2 家保留划分；资料不足时先记录实际数量和局限，不能虚构补齐。保留题/答案在受控外部路径保存，仓库仅登记不泄题的清单。
- **验收：**数值答案可由人工按原文复算；所有必要资料有取得方式和 hash；开发与保留资料无公司/版本泄漏；在生成候选前冻结评分与硬门。人工未核对的答案明确标成待标注，不作为 golden。

## S03：运行可复验基线，保存实际失败

- **依赖：**S01、S02。
- **工作与落点：**在隔离的测试身份和存储范围运行现有公司研究，建立研究专用 runner/适配；不直接拿看板生成 benchmark 替代。先小样本校准调用预算和证据，再执行冻结的开发集。服务与鉴权失败、未进入模型、任务不支持分别记录。
- **交付：**固定资料响应与运行 manifest、原始结果、逐题判断、usage 完整性、失败阶段、可复现命令；把脱敏汇总写入 `baseline.md`。不能提供原始资料的运行标明不可离线重放。
- **验收：**每个实际运行有身份、版本、终态和结果位置；失败也完整保存。现有系统不支持双期问答时标 `unsupported`，不得包装成同题准确率对照；S13 再建立第一版完整能力基线。步骤完成代表基线可信，不代表旧实现所有任务通过。

## S04：定义任务、计划、文档、证据和报告版本合同

- **依赖：**S01、S02。
- **工作与落点：**扩展 `src/lib/company-research/contracts.ts` 并按职责拆模块；定义公司身份、两期范围、asOf、问题、请求版本、计划 revision、来源 hash、页码/表格定位、财务事实、claim、报告 revision、事件与兼容读取。明确逻辑任务和执行 attempt 的关系。
- **交付：**`contracts.md`（新增）及实际 schema、类型、状态转换说明。将需求版本、计划版本、报告版本与运行 fencing generation 分开；定义 partial、不可比较、证据不足及计划变更冲突。完整请求进入幂等摘要。
- **验收：**旧请求/报告按明确规则可读；非法版本、同幂等键异输入、失配引用、错误期间被拒绝；合同测试覆盖这些行为。S16 修改计划、S17 更新报告可以用该合同表示，无需覆写旧事实。

## S05：落地持久化、隔离和兼容迁移

- **依赖：**S04。
- **工作与落点：**通过 `prisma/schema.prisma`、新的追加迁移及研究 store 保存版本关系、来源索引和状态。复用 actor/project 授权边界，按 S01 实际归属模型派生作用域。大 PDF/解析产物采用受控文件或对象目录，数据库保存索引、hash、位置与状态。
- **交付：**可在测试库演练的迁移、repository/API 边界及旧状态读取方案；明确资料所有者、保留和删除语义，文档同步到数据字典。
- **验收：**同请求重试不重复创建；并发写版本有冲突检测；其他用户不能读来源正文或报告；旧报告仍可读；测试库从旧 schema 升级及代码回退场景有记录。不删除/重写生产资料或历史迁移。

## S06：统一财报发现、导入和来源时间证据

- **依赖：**S05。
- **工作与落点：**扩展 discovery、connectors、network 和 source store；复用当前公告、DeepSeek Search/Fetch 与 PDF 通路。按公司和两期定位原始资料，来源去重、版本化并保存取得时间、披露时间与报告期。
- **交付：**来源清单和内容寻址的原始文件；用于研究的文档状态（可读、日期待核查、晚于截至时间、下载失败等）。来源链接不等于已经取得正文。
- **验收：**相同 bytes 可复用，来源修订保留新版本；重定向/内网 URL、超大内容与非法类型被现有网络边界约束；未来资料和未知发布日期按冻结规则处理；原始内容 hash 可复核。

## S07：实现带定位的文本 PDF / HTML 解析

- **依赖：**S06。
- **工作与落点：**在可替换 parser port 后实现文本 PDF/HTML 适配，将正文组织为有稳定 ID 的页、段落和表格块，保留阅读顺序、原文以及解析器版本。沿用可用文本解析能力，不在通用 PI 内核加入 PDF 逻辑。
- **交付：**统一文档块合同和解析产物；记录 PDF 文件页码与印刷页码的区别、截断页数、失败页。仅在确有坐标时提供 bounding box。
- **验收：**固定资料中的引用能还原到正确页和文本；重复解析 ID/内容版本关系稳定；截断与缺页可见；空正文不能被标为解析成功。至少一个跨页段落和一个 HTML 资料通过定位验证。

## S08：接入扫描件 OCR 与表格结构解析

- **依赖：**S07。
- **工作与落点：**通过 parser port 试点 Docling；评估中文、扫描页、跨页表格、合并单元格、括号负数及脚注单位。先记录运行环境、资源和依赖版本，再选择进程/服务边界；若更换实现须更新 D03。
- **交付：**OCR/表格适配、质量标记和文本解析回退策略；样本对照表包含原图、提取结果、人工核对结果。首次解析可产生缓存，错误缓存可以按 parser version 失效。
- **验收：**扫描件有可核对的页定位；关键金额、负号、小数点、列头和单位有人工抽查；低质量块不会无提示进入已核实事实；超时可停止并保留 partial，不阻塞其他任务。

## S09：实现确定性的财务口径与变化计算

- **依赖：**S07、S08。
- **工作与落点：**在研究领域层建立 FinancialFact 与比较函数；包含指标、原值、数值、币种、单位、期间起止、累计/单季、合并/母公司、披露时点、重述版本及引用。复用 market-data 已有正确计算能力。
- **交付：**利润/现金流/风险所需的指标映射和变化结果；金额使用明确精度策略，百分比不靠模型心算。保留原始披露值与规范化值。
- **验收：**万元/亿元、负数、零/负基数、年度/半年、累计转单季、重述等用例符合冻结规则；不可比较明确返回原因；缺数据不能补零。累计转单季需要完整同口径前期数据，否则拒绝计算。

## S10：建立带来源定位与时间过滤的检索工具

- **依赖：**S07、S08、S09。
- **工作与落点：**为本任务授权范围内的文档块建立索引；先做公司、报告期、asOf 与字段过滤，再做中文词法/关键词检索和排序。返回 source/chunk ID、页码、表格定位、原文和分数。增加让 Agent 重查较早来源的工具。
- **交付：**检索接口、开发集基线和上下文拼装策略；需要 embedding/reranker 时只在开发集做对照并登记版本、成本与引入理由。先裁权限再检索。
- **验收：**超过 8 份来源时仍能找到较早证据；过期、未来、其他用户文档不泄漏；固定问题有 Recall@k 或准确定位命中率及实际分母；工具输出有界且可返回全文定位供继续读取。

## S11：把双期研究计划接入现有 Agent 循环

- **依赖：**S04、S05、S09、S10。
- **工作与落点：**扩展研究 runtime/tools，把三个问题拆成可执行计划，按需检索、检查缺口并补查。使用现有 PI 循环和受信工具；上下文由任务版本、计划、已核查事实、问题缺口及相关片段组成。
- **交付：**首版研究 Skill/提示词、计划状态与 checkpoint、工具输入输出合同、无进展停止策略。写入进度只代表执行状态，不代表业务结论已正确。
- **验收：**固定文档完成三类问题的执行路径；重复搜索会调整策略或停止；预算耗尽、取消、正文缺失均产生明确终态/partial。恢复不重置累计预算和开始时间，不持久化隐藏思维。

## S12：建立 claim 到证据的分层核验

- **依赖：**S09、S11。
- **工作与落点：**扩展 evidence/ledger，分别检查身份与时间、原文存在性、数字口径、语义支持、证据冲突。区分事实、推断与意见；“现金流下降的原因”需要支持其解释的证据，不能只由两个相关数字推定因果。
- **交付：**逐 claim 核验结果、冲突/不足原因与局部修复入口；语义检查来自人工或经过校准的 reviewer，标明是否独立于生成模型。
- **验收：**错误公司、错报告期、伪造引用、真实原文支持相反结论、单位错配和未来信息均有负例；确定性通过不能冒充语义已证明。软评分不能覆盖硬门失败；修复只影响关联证据和结论。

## S13：形成报告与双期变化表的端到端交付

- **依赖：**S11、S12。
- **工作与落点：**通过报告组装服务与研究 API 交付三个问题的结论、变化表、引用、未解决项及方法说明；结构化表格直接使用规范化事实。保留草稿、partial 与已验收报告的区别。
- **交付：**固定资料的真实模型运行结果，以及新能力 G0 基线（若 S03 无同能力对照）；保存模型、Skill、工具、合同、资料与评测版本。API 序列化不得泄露模型凭据或全部原文。
- **验收：**至少一个完整双期案例真实跑通并人工核查关键数字/解释；一个资料不足案例诚实交付 partial；报告仅引用本次可用证据，断点恢复不重复提交。fixture 通过不能替代本步真实运行。

## S14：实现研究工作台和可恢复事件流

- **依赖：**S04、S13。
- **工作与落点：**拆分 `CompanyResearchClient` 的状态控制和展示组件，增加计划、阶段、资料、结论卡片与变化表。服务端事件携带 sequence、task/run ID 和版本；复用 SSE，评估 AG-UI 子集适配并记录决定。
- **交付：**可浏览的研究工作台、版本化事件合同、断线恢复和快照合并逻辑；后端状态是唯一权威。采用 AG-UI 时有明确映射与契约测试，不能仅因事件命名相似就宣称兼容。
- **验收：**增量事件、重复事件、乱序、刷新、切换 run、断线重连和终态均正确显示；不会把旧任务数据写入当前界面。桌面/移动端和键盘访问可用，首屏及时反馈进度。

## S15：实现点击结论定位原文的证据阅读器

- **依赖：**S07、S08、S12、S14。
- **工作与落点：**增加授权文档读取 API 与证据侧栏/阅读器，展示 source、页码、原文、表格、披露时点及核验状态；仅有真实定位时高亮。以确定的 source hash 读取对应版本。
- **交付：**结论—引用—原文双向导航，支持从变化表查看两个期间的证据；未知日期、OCR 质量差和文档缺失有明确说明。
- **验收：**至少一个文本 PDF 和一个扫描/表格案例点击定位正确；无坐标时使用页/文本定位且不伪造高亮；来源切换及访问权限可靠；文档 HTML/链接内容不能注入脚本。

## S16：支持用户修改计划并安全重新规划

- **依赖：**S04、S05、S11、S14。
- **工作与落点：**加入计划编辑/API，首版允许修改研究问题和两期范围。使用 expectedRevision/幂等键处理冲突；新版本持久化后，在工具边界停止旧执行并重新规划，复用仍合格的证据。变更公司或 asOf 创建明确的新请求版本/运行。
- **交付：**计划修订事件、影响范围、旧执行失效和新执行承接；显示“变更已接收/等待安全边界/新版本执行中”。不声称恢复旧 Provider 的隐藏会话。
- **验收：**双浏览器同时修改只有合法版本获准；重复提交不产生重复修订；旧 worker 的晚到结果不能覆盖新版本；取消优先级、重启、预算耗尽均有用例。同一逻辑请求的修订不自动延长总预算。

## S17：支持新财报触发研究更新和报告差异

- **依赖：**S06、S09、S13、S15、S16。
- **工作与落点：**用户主动检查新公告，按 source hash、披露/报告时点判断新版本；建立证据到 claim 的依赖，只对受影响结论补查。生成新 report revision 并展示数值变化、支持/修订/撤回及原因。
- **交付：**版本历史、报告差异和证据差异；旧报告按旧 asOf 和原始资料保留，新报告有独立时点与来源。
- **验收：**同文件重复检查不重复交付；新增财报或重述触发正确差异；无变化不伪造更新；晚披露资料不会倒灌旧报告。至少一个支持旧结论、一个推翻/撤回旧结论的固定案例可复现。

## S18：验证恢复、隔离、资源限制和运行可观测性

- **依赖：**S05、S11、S14、S16、S17。
- **工作与落点：**以 task/run/plan/report 版本关联解析、检索、模型、工具和交付观测；复用现有日志/治理。按需增加 OpenTelemetry 适配，避免重复建监控平台。补故障注入与服务间边界测试。
- **交付：**`reliability.md`（新增）的实际矩阵、故障证据、恢复操作和资源说明；记录耗时、usage、估计成本与计费口径，未知值保持未知。
- **验收：**worker 中断/接管、旧 fencing 写入、SSE 丢失、模型超时、解析失败、取消期间回调可验证；跨用户访问、来源提示注入、SSRF 和恶意文档均有针对性测试。至少一次隔离环境真实进程中断实验；模拟结果与真实结果分开。

## S19：完成评测对照和一个 Skill 改进实验

- **依赖：**S02、S03、S13、S18。
- **工作与落点：**先运行冻结开发集，用失败轨迹定位一个可通过 Skill 改善的问题，离线生成一个候选。固定模型、数据、工具、rubric、预算及运行环境，按相同问题配对比较；记录开发实验次数。最终候选冻结后再验保留集。
- **交付：**`evaluation-results.md`（新增）、逐题结果、候选 diff、版本/hash、失败归因、实际样本数/重复次数/区间及成本；独立 judge/人工校准状态明确。候选不合格就保留原版，负结果也如实记录。
- **验收：**业务硬门不被平均分掩盖；资料固定、版本可比较；首轮与修复后完成率分开，成本包含失败和重试。只有相同能力/样本/规则才报告提升；否则报告绝对水平。S02 约定的首版质量门达到后才进入交付，未达标回到对应步骤修复并重开受影响状态。

## S20：完成综合验收、演示和面试证据包

- **依赖：**S01—S19 均通过各自验收。

## 每步共用的完成条件

1. 本步验收项有实际结果，明确区分静态核对、fixture、真实依赖和人工检查；待运行项不能勾成通过。
2. 改动在规定模块内，接口和数据有版本，相关现有行为未被无意破坏。
3. 本步相关检查完成；既有故障有修改前证据，未完成检查有原因和下一动作。
4. 运行证据可找到且不会因清理 `tmp/` 失去唯一证明；私有资料不提交。
5. 更新 `progress.md`，必要时追加决策；下一会话知道从哪个文件/动作继续。

仅文档/计划步骤按自身产物验收，不要求无关 E2E。S03 可记录失败基线，S08 可如实记录选型失败并实施替代；这些不能被用来跳过后续真实业务验收。
