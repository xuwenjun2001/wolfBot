# 消融实验登记

> 状态：`pending_review`。本页是 U03 的登记提案和框架验证记录，未获得真实模型实验授权。G0 的 rubric、可回答性标签、样本与预算确认仍待完成。

## 本次交付范围

`run-agent-ablation.ts` 负责协议、任务矩阵、预算账本、结果保存和评分，执行通过可信 adapter 的 `runtimeOptions.variant` 注入。A、B、B2、C1、C2、C2-peer 均可做框架 mock；mock 返回空报告和明确的框架错误，树、Token 与阶段耗时均为模拟值，实际模型调用为零。mock 成功只说明传参与证据保存通路可用。

当前 CLI 没有接入生产研究 adapter，`--provider=real` 会关闭执行并列出阻塞。U13/U33/U37 完成相应运行时后，须由可信组合层接入 adapter，不能用任意脚本路径加载执行器。adapter 必须声明实际支持的变体、实际研究模型/推理配置、整个父任务的 40 次工具 / 20 分钟预算、输入 Token 上限执行能力及一次性测试数据库证明。不能把 C2 的预算解释为每个子 Agent 各 40 次 / 20 分钟。

缓存提议统一为 `cold`，每个 arm 与重复遵守相同的冷启动定义；若采用 `warm`，另建 campaign 并登记预热步骤、共享范围和顺序。当前 mock 只传递这一条件，不验证生产缓存效果。真实 adapter 接入时还需冻结原件/解析版本、检索参数和索引版本、工具/权限、收尾预算以及各阶段实现；比较检索优化 R 时独立登记唯一变化。

3 变体探索不能分别识别 B2 的往返收益和 C1 的上下文隔离效应；需要这些结论时选择完整提案。两项是互斥的完整 campaign 提案，不能先跑 50M 再在同一 campaign 提高 cap。失败、部分结果和未知用量都保留；停止后不能重置预算继续。

## 统计、选择与停止规则

1. 每例、每次重复、每个变体都在预登记矩阵中，包括失败与未启动任务；零用量只用于确认没有启动的任务，未知消耗保持 `null`。目录不可覆盖或静默重试，完整 campaign 使用排他锁和追加账本。
2. 比例保留完整分母与 Wilson 95% 区间。v1 定义、阈值和历史结果不变；v2 另报可回答支持、正确弃答、错误断言、漏答及确认状态。正式 v2 需要人审冻结 rubric、标签和必要的报告语义复核；当前只有 diagnostic。
3. 同一题目的两变体结果成对重采样：10,000 次、seed `20261024`、95% percentile 区间。重复序号与同行对 ID 进入题目键。比较读取账本已校验的逐次结果，不信任可改写的汇总分数。协议或配对不齐即拒绝，不丢掉失败补齐可比较子集。
4. 题目级 bootstrap 未消除公司内、重复间及同行重叠的相关性，小样本只报告结果和不确定性，不声明普遍提升或统计显著。框架 mock 的零分、差值和模拟时间都没有产品质量含义。
5. 候选先满足原硬门和已确认质量要求，再比较真实 Token、成功父任务成本和耗时。没有达到质量门时不按速度挑优；多 Agent 只在证明有收益的任务分层启用。若多个候选均达标而成本区间无法区分，优先单 Agent，再用新的独立登记解决不确定性。
6. 已知输入达到 cap、出现未知输入、adapter 超额、父任务预算耗尽时停止后续启动；保留已产生结果及超额。因进程中断留下 `started.json` 而没有结果时，拒绝自动继续，先完成显式用量核对。
