# 原生行情看板

2026-09-06，`extend/dashboard.cmd` 的主要行情观察功能已迁入 wolfbot。入口为产品导航中的“行情看板”，页面路径 `/market-dashboard`。它使用现有 React 页面、Next 鉴权 API 和 Python market-data 服务，不需要启动 CMD、PowerShell 看板或 8765 端口。

## 启动与使用

在项目根目录运行：

```powershell
npm run dev -- --port 3001
```

等待启动器输出 ready，再打开 `http://localhost:3001/market-dashboard`。`npm run dev` 会按项目现有方式启动 Web 和市场数据服务；`npm run dev:web` 只启动 Web，使用时需要已有 market-data 服务。市场 API 默认地址为 `http://127.0.0.1:8000`。

| 模块 | 已实现功能 | 来源 |
| --- | --- | --- |
| 市场概览 | 上证、深证、创业板、科创50、沪深300指数及源报价时间 | 腾讯财经 |
| 板块资金 | 行业/概念排名、分页、搜索、列排序、日内累计主力净流入曲线 | 东方财富 |
| 宽基 ETF 观察 | 13只ETF报价、分时价格、可启停的分钟成交额异动观察 | 腾讯财经 |
| 近三日资金 | 选择板块，展示最近三个交易日日级累计净流入曲线 | 东方财富 |
| 涨跌停分析 | 指定日期涨停、跌停、炸板、昨日涨停池；强势股复盘；近90日前复权收盘走势 | 东方财富、BigAMap、腾讯财经 |

搜索与表头排序作用于当前页；列表每页100条，最多10页。龙虎榜单日报表上限500条，超过上限会明确提示不可用，不静默截断。选中的股票或板块详情位于列表下方。

涨跌停、龙虎榜默认查询上海时区今天，可以修改“查询日期”。休市日、源尚未发布或源不支持的历史日期可能无结果；不会静默替换日期。强势股复盘及机构持仓按各自源日期展示，不承诺支持任意历史日期。

## 数据口径和原版差异

### 市场成交额与四大指数（market-layout）

该模块位于指数概览与业务页签之间。四个指数（上证、深证、创业板、科创50）均可选择，所选指数和沪深合计支持成交额／成交量切换，默认成交额，同时展示当日、昨日、MA5。悬停或键盘时间滑块显示两组差额和变化率；顶部沪深摘要跟随指标选择，分别标明当前截止时间和基准比较时间。

MA5 是**当日前五个实际交易日、相同时刻累计值的算术平均值，不含当日**。例如今日10:30与前五日各自截至10:30的累计值比较。五日不足或某日分钟缺失时，仅在五日均可连续累计的区间计算MA5，其他时点显示缺失及 N/5 积累进度；不拿更早日期顶替，不把不足五天的平均数叫MA5。昨日与MA5独立可用，只有当天数据时仍画当天曲线。

原有 `index-session?index=sh|sz|cy|kc`、`market-turnover` 资源增加 `metrics.amount`、`metrics.volume`，保留旧 `comparison` 成交额接口。每项指标返回当前日期/截止、单位、实际五日日期、样本数、昨日与MA5各自截止及原因、分钟累计值/差额/变化率。`fetchedAt`/`retained` 标记复用的分钟字段，不用新请求时间伪装旧值。金额为人民币元，成交量为手；沪深合计不重复加入创业板或科创50。

分钟累计必须从09:30连续开始，跳过午休；量额独立校验，不补零、不用价格乘成交量估算金额。分母为零时变化率为空；两市日期必须一致，合计以共同截止时点计算。休市时显示最近交易日，不将其标为当天实时行情。交易日历优先使用已维护数据，缺失时验证腾讯宽基指数真实交易日期；无法确认则不推算昨日。日历暂不可用时，后台在工作日行情时段最多每五分钟探测一次，仍以源返回的实际日期为准，不据此生成交易日历。源领先线仅表示东方财富提供的数值。

### 五日归档与后台采集

先应用幂等迁移 `sqls/010-dashboard-index-sessions.sql`，创建 `quant.dashboard_index_sessions`。按指数、交易日保存分钟量额、来源、单位、获取时间和完整性；保留前五日加当日。Redis只做短期缓存，重启不会清空归档。按分钟合并，空字段、较短序列和单日降级不会抹掉已知历史；确认交易日期后才清理窗口外记录。

市场服务启动时尝试补采；交易时段每分钟采集四项指数，午休暂停，15:05补取收盘数据，失败每五分钟重试至18:00。任务不依赖浏览器，PostgreSQL advisory lock保证同一数据库只有一个后台采集者。历史接口最多请求五日窗口，失效后退避五分钟，使用延迟源保留当天数据；首次安装可能需要逐日积累，不能保证立刻得到五个历史日。

`QUANTPILOT_DASHBOARD_COLLECTOR_ENABLED=false` 可关闭后台采集，默认开启；页面查询仍会归档有效数据。数据库不可用时保留可取得的当前数据，明确提示历史留存故障。停止采集或服务离线期间的历史补齐取决于上游实际覆盖范围。

### 看板加载与异常状态

首次加载显示占位，同一查询刷新保留旧内容，切换指数／日期／筛选时隔离旧查询。网络失败以及HTTP成功但业务不可用均保留已有有效数据和原始获取时间，显示局部重试与20秒失败冷却；每分钟检查更新，页面隐藏时暂停。正常空结果、筛选无匹配、后台处理中、部分可用、历史不足和不可用分别提示，单模块故障不阻断其他模块。MA5和昨日基准缺失不隐藏当天曲线。

涨跌家数分别统计沪市A股、深市A股、创业板全体或科创板全体，而非指数成分股。首次返回 `pending`（后台统计中），分页完成后才发布家数；上涨、下跌、平盘与无报价分开计数，无报价不等于停牌。每页100条、最多80页、活动任务限时180秒，单实例一个扫描任务，范围内请求合并。后台每页让交互请求优先并遵守东方财富限流，统计缓存5分钟；失败退避20秒，最多保留30分钟内的旧完整快照。进程退出取消任务；Redis可共享结果，但任务合并和调度为实例内机制。页面每分钟获取完成状态，首次统计可能需要数分钟。

对应测试：`test_market_layout.py`、`test_turnover_history.py`；真实数据库验证用 `test_dashboard_archive_postgres.py`（仅本机临时表）。浏览器回归运行 `node scripts/checks/check-market-dashboard-visual.cjs`，使用请求拦截样本验证，不向数据库写入样本。

- 每组数据展示来源、业务日期、获取时间和缓存状态。`fetchedAt` 是获取时间，不能代替 `tradeDate`。日期未知或早于今天时明确标注。
- 金额以人民币元传递，界面换算万/亿；涨跌幅为百分点；期货持仓为手。缺失值显示 `—`，不填零。
- 三日资金曲线是三个日级节点的累计值；不足三个节点时标记部分数据，不补造分钟曲线。
- ETF异动观察需手动启用：仅使用09:31–11:30、13:01–15:00的盘中记录，并保守排除最后一个可能未完成的分钟；成交额相对之前最多30个有效分钟中位数计算倍数，至少8个有效基线样本。1.6倍标为放大，2.4倍标为脉冲。该算法是本模块的明确规则，不是对原包复杂信号状态机的逐项复刻，也不能识别资金主体。
- 未导入原HTML内置的2026年6月龙虎榜/监管快照、桌面抓包或8765页面的localStorage。原版游资身份标签、屏蔽设置及ETF历史信号日志未迁移；席位按营业部公开名称展示。
- 未获得有效数据时显示不可用/暂无记录，源成功返回空名单不等于市场没有风险。上游临时失败时最多保留30分钟内上次成功的数据，同时保留原始日期、获取时间和失败提示。

## 接口与运行边界

浏览器仅访问同源 `/api/quant/market-dashboard/[resource]`。Next执行 `quant.data.read` 权限检查，并将请求交给 `/api/v1/market-dashboard/{resource}`；Python读取固定上游。页面复用现有主题及产品导航，不加载远程JSONP脚本。

资源白名单：`overview`、`etfs`、`sectors`、`sector-history`、`limits`、`strong`、`watch`、`dragon-tiger`、`seats`、`themes`、`theme-stocks`、`institutions`、`minute`、`kline`。参数严格校验，拒绝重复参数、未来/无效日期、越界分页、任意URL和路径输入。北交所43/83/87旧代码需先迁移为920代码。

沿用 `QUANTPILOT_MARKET_API_URL` / `QUANTPILOT_MARKET_API_BASE_URL`，并遵守现有市场服务开关。Next在服务端传递 `QUANTPILOT_MARKET_ADMIN_TOKEN`；浏览器不接触该令牌。Python路由使用现有 `require_market_admin`：配置令牌时校验令牌，未配置时仅允许现有本机开发模式。远程部署沿用项目的网络隔离、登录权限和令牌配置；本次集成没有新增数据库迁移。

缓存使用现有Redis，故障时退回有上限的内存缓存。报价/分时30秒，持仓/龙虎榜/席位/K线/成分股300秒，其他120秒；失败响应缓存20秒。页面可见时每分钟检查更新，隐藏时不再发起轮询，离开页签取消未完成请求。手动刷新仍遵守服务端缓存与限流。

每个Python服务实例最多4个看板查询并发，东方财富请求串行且间隔至少1秒加抖动，其他源最多3个请求并发。传输中断只对固定东方财富域名重试一次；行情主机可切换到同源的延迟行情主机。历史接口仍使用历史主机，避免把单日结果当作三日历史。总查询、连接及读取均有超时。缓存可跨实例共享，但请求合并与限流为进程内机制；增加worker/副本前需评估上游总请求量，不能把它当成全局限流。
