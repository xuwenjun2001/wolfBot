# NGA 发言雷达

Windows 本地应用，同时监控 UID [60916468 在帖子 47710788 中的发言](https://ngabbs.com/read.php?tid=47710788&authorid=60916468&opt=262144)，以及 UID [150058 在帖子 47288722 中的发言](https://ngabbs.com/read.php?tid=47288722&authorid=150058)。每个目标只检查指定帖子中的发言，自动跟随新增分页；提供的第 6 页链接不会将监控固定在这一页。可见范围由 NGA 决定。

双击 `启动监控.vbs`。也可执行 `python watcher.py`。使用 Python 3 标准库，无需安装第三方包。

- 每个用户各自每轮成功后 60 秒再检查；明确返回 `ERROR:2048 > 服务器忙,请稍后重试` 或 HTTP 503 空响应时，等待 0.5 秒继续请求，直到恢复。等待时间从上一请求结束后计算，连续请求的开始时间还会相隔一次请求耗时。界面显示具体错误码及重试间隔。重试仍属于该用户的同一轮检查，不重叠执行；一个用户重试不影响另一个用户的检查，暂停和退出会取消两个用户的重试。登录失效、网络错误及其他访问限制分别提示。
- 新加入且没有已读记录的目标首次建立基线，不提醒已有发言；已有用户的进度、未确认提醒和飞书待发送队列保留。从搜索切换为单帖时，沿用已验证且属于指定帖子及目标作者的最新 PID，归档原搜索进度，并从帖子末页向前补查。UID 60916468 对应帖子 47710788，UID 150058 对应帖子 47288722。
- 跨帖搜索按分钟边界补查，超过 20 页保留进度并报错；单帖按 PID 补查，从上次成功页核实当前分页，再从末页向前查到已读 PID，超过 200 页保留进度并报错。UID 60916468 切换时使用已验证的第 6 页作为起点。补查所需的任一页失败都不会推进该用户的进度；补查期间新增分页也需验证后才能提交结果。
- 用户搜索页需要 NGA 登录态。点击“NGA 登录态”，从已登录浏览器的网络请求头复制 Cookie，在本地窗口粘贴保存。也可运行 `python nga_auth.py` 单独打开设置。登录态保存在 `%LOCALAPPDATA%\NGAWatcher\nga-session.json`；请求仅发往 NGA 原站，不向跨站跳转发送 Cookie，不记录到日志。过期后需重新填写。
- 运行期间使用 CookieJar 接收 NGA 同站响应更新的 Cookie，再用于后续请求和同站跳转；这些会话更新保存在内存中。手动保存新的登录态会清除上一份会话，重启仍使用本地保存的登录凭证。
- 新发言弹出占屏幕 90% 宽、85% 高的置顶窗口，每 2 秒播放 Windows 提示音并闪烁任务栏，直到确认；可以单独静音。系统音量、静音和锁屏会影响实际提醒效果。
- 支持飞书企业自建应用机器人单聊通知，点击“飞书设置”填写 App ID、App Secret 和接收人，勾选启用并保存。可用飞书邮箱、Open ID 或 User ID 指定接收人。配置方式见 [飞书单聊配置.md](飞书单聊配置.md)。
- 飞书通知包含实际作者 UID、发言时间、最多 1200 字正文和该条发言链接。两个用户共用已配置的机器人单聊，桌面弹窗和最近发言列表也标明作者。失败的消息独立保存在进度文件里，每 60 秒重试；关闭本地弹窗不影响重试。成功后每 2 秒最多继续发送一条，重启后继续处理待发送消息。
- 「测试强提醒」可立即体验提醒，测试不修改监控进度。
- 可最小化保持后台运行；关闭窗口会确认是否退出。电脑睡眠、关机、应用退出期间不轮询，恢复后补查。
- 任一用户连续 3 次检查失败会弹窗提示；错误不会被当成无新发言，各自的失败次数单独计数。
- 不添加随机查询参数；使用网站的普通查询地址和浏览器常用请求头。JSON 格式不完整时最多尝试两次，再读取同页普通网页；“服务器忙”等待 0.5 秒后重试，“需要登录”提示更新登录态。
- 跨帖搜索只读取结果里 `__P` 的作者、PID、正文和回复时间；外层作者和时间属于主题。单帖接口额外严格校验主题 ID、目标 UID、页码和完整条数。网页兜底校验目标 UID、主题或分页、真实发言标识和结束标记；引用中的 PID 不作为发言 ID。搜索网页列表没有可靠回复时间时，使用已经验证的缓存或读取对应发言详情；详情也无法验证时保留原进度。
- 按主题 ID 和 PID 去重，兼容各个主题的主楼 PID 0。搜索 JSON 提供秒级时间，详情页可能只有分钟，因此补查边界按分钟保存，并保留边界内所有已见发言标识，避免同一分钟的新回复被遗漏。界面分别显示两个用户最近一轮来源（JSON / HTML / 混合）、上次成功时间和下次检查倒计时。
- 只有明确访客会话错误才刷新 Cookie；截断响应不会触发反复刷新。诊断日志保存在 `%LOCALAPPDATA%\NGAWatcher\watcher.log`，记录耗时、字节数和兜底结果，自动轮转，不记录会话 Cookie。
- 搜索页不提供精确总条数和总页数，界面基线数量表示当时首页已读取的条数。程序不自动登录、不发帖；需要验证码或账号登录时，在浏览器完成后更新本地登录态。

进度与未确认发言保存在 `%LOCALAPPDATA%\NGAWatcher\state.json`，以临时文件加替换的方式保存。`authors` 按 UID 保存各自的监控模式、边界和最近发言，未确认提醒与飞书待发送队列共用；首次升级自动迁移原用户进度，切换监控范围前的进度保存在 `previous_monitors`。删除该文件将重新建立两个用户的基线。没有配置开机自启。

飞书凭证保存到当前 Windows 用户的 `%LOCALAPPDATA%\NGAWatcher\feishu.json`，不写入项目或日志；访问令牌只在内存中缓存。启用后新检测到的发言会发送，启用前已检查过的历史发言不会自动补发。若电脑退出、休眠或无网络，则恢复后继续处理。发送请求使用稳定消息 UUID 降低网络超时重试导致的重复，最终去重受飞书服务端的有效期限制。

验证：`python -m unittest discover -s apps/nga-watcher -v`；UI 冒烟：`python apps/nga-watcher/watcher.py --smoke-test`（无声、自动退出）。
