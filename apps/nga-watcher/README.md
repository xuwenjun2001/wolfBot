# NGA 发言雷达

Windows 本地应用，可监控 NGA 发言、上证指数和科创50的盘中放量，并查看全 A 成交额。NGA 按 UID 分别检查指定帖子的发言，并跟随新增分页。

- UID 60916468 在帖子 47908854 的发言。[打开监控页](https://ngabbs.com/read.php?tid=47908854&authorid=60916468)
- UID 63513284 在帖子 47908854 的发言。[打开监控页](https://ngabbs.com/read.php?tid=47908854&authorid=63513284)
- UID 150058 在帖子 47288722 的发言。[打开监控页](https://ngabbs.com/read.php?tid=47288722&authorid=150058)

双击 `启动监控.vbs`。也可执行 `python watcher.py`。使用 Python 3 标准库，无需安装第三方包。

## 监控行为

- 每个用户各自每轮成功后 60 秒再检查。明确返回 `ERROR:2048 > 服务器忙,请稍后重试` 或 HTTP 503 空响应时，从请求结束开始等 0.5 秒再试，直到恢复。各用户独立检查，重试期间仍属于同一轮。暂停或退出会取消所有重试。界面分别提示站点忙、登录失效、网络错误和其他访问限制。
- 首次检查新目标时建立基线，之后发现新发言才提醒。从搜索或其他帖子切换时，归档原进度，并尝试沿用已验证且属于新帖子及该作者的最新 PID。没有相符记录时建立新帖基线。原有未确认桌面提醒随进度文件保留。
- 跨帖搜索按分钟边界补查，超过 20 页保留进度并报错；单帖按 PID 补查，首次从第 1 页核实分页，随后从上次成功页核实当前分页，再从末页向前查到已读 PID，超过 200 页保留进度并报错。经核实的空页会继续向前补查。补查所需的任一页失败都不会推进该用户的进度；补查期间新增分页也需验证后才能提交结果。
- 用户搜索页需要 NGA 登录态。点击“NGA 登录态”，从已登录浏览器的网络请求头复制 Cookie，在本地窗口粘贴保存。也可运行 `python nga_auth.py` 单独打开设置。登录态保存在 `%LOCALAPPDATA%\NGAWatcher\nga-session.json`；请求仅发往 NGA 原站，不向跨站跳转发送 Cookie，不记录到日志。过期后需重新填写。
- 运行期间使用 CookieJar 接收 NGA 同站响应更新的 Cookie，再用于后续请求和同站跳转；这些会话更新保存在内存中。手动保存新的登录态会清除上一份会话，重启仍使用本地保存的登录凭证。
- 新发言弹出占屏幕 90% 宽、85% 高的置顶窗口，每 2 秒播放 Windows 提示音并闪烁任务栏，直到确认；可以单独静音。系统音量、静音和锁屏会影响实际提醒效果。
- 支持飞书企业自建应用机器人单聊通知，点击“飞书设置”填写 App ID、App Secret 和接收人，勾选启用并保存。可用飞书邮箱、Open ID 或 User ID 指定接收人。配置方式见 [飞书单聊配置.md](飞书单聊配置.md)。
- 飞书通知包含实际作者 UID、发言时间、最多 1200 字正文和该条发言链接。所有监控目标共用已配置的机器人单聊，桌面弹窗和最近发言列表也标明作者。发送失败的消息每 60 秒重试，成功后每 2 秒最多继续发送一条。重启时清空旧的飞书待发送队列。每位用户首次成功检查只补进度，从下一轮开始推送检测到的新发言。
- 「测试强提醒」可立即体验提醒，测试不修改监控进度。
- 可最小化保持后台运行；关闭窗口会确认是否退出。电脑睡眠、关机、应用退出期间不轮询，恢复后补查。
- 任一用户连续 3 次检查失败会弹窗提示；错误不会被当成无新发言，各自的失败次数单独计数。
- 不添加随机查询参数；使用网站的普通查询地址和浏览器常用请求头。JSON 格式不完整时最多尝试两次，再读取同页普通网页；“服务器忙”等待 0.5 秒后重试，“需要登录”提示更新登录态。
- 跨帖搜索只读取结果里 `__P` 的作者、PID、正文和回复时间；外层作者和时间属于主题。单帖接口额外校验主题 ID、目标 UID、页码，以及声明的本页条数和实际返回条数。NGA 分页可能保留不可见楼层，出现条数少于分页槽位时，要求 JSON 提供真实楼层，并读取完整网页，逐条核对楼层、PID、作者、时间和正文；两种来源一致才接受空楼层。两种来源不一致、响应截断或字段缺失时保留原进度。网页还校验结束标记和重复发言容器，引用中的 PID 不作为发言 ID。搜索网页列表没有可靠回复时间时，使用已经验证的缓存或读取对应发言详情；详情也无法验证时保留原进度。
- 按主题 ID 和 PID 去重，兼容各个主题的主楼 PID 0。搜索 JSON 提供秒级时间，详情页可能只有分钟，因此补查边界按分钟保存，并保留边界内所有已见发言标识，避免同一分钟的新回复被遗漏。界面分别显示各用户最近一轮来源（JSON / HTML / 混合）、上次成功时间和下次检查倒计时。
- 只有明确访客会话错误才刷新 Cookie；截断响应不会触发反复刷新。诊断日志保存在 `%LOCALAPPDATA%\NGAWatcher\watcher.log`，记录耗时、字节数和兜底结果，自动轮转，不记录会话 Cookie。
- 搜索页不提供精确总条数和总页数，界面基线数量表示当时首页已读取的条数。程序不自动登录、不发帖；需要验证码或账号登录时，在浏览器完成后更新本地登录态。

进度与未确认发言保存在 `%LOCALAPPDATA%\NGAWatcher\state.json`，以临时文件加替换的方式保存。`authors` 按 UID 保存监控模式、边界和最近发言，各目标共用未确认桌面提醒和飞书待发送队列。首次升级自动迁移原用户进度，切换监控范围前的进度保存在 `previous_monitors`。删除该文件将重建所有基线。应用需手动启动。

飞书凭证保存到当前 Windows 用户的 `%LOCALAPPDATA%\NGAWatcher\feishu.json`，不写入项目或日志；访问令牌只在内存中缓存。启用后，启动首次检查之后检测到的新发言会发送；停机期间积压发言及旧的待发送队列不会补发。若电脑退出、休眠或无网络，则恢复后继续检查。发送请求使用稳定消息 UUID 降低网络超时重试导致的重复，最终去重受飞书服务端的有效期限制。

## 盘中成交额

主窗口显示东方财富全 A（沪深京，800004）的累计成交额，单位为万亿元。取最近完成的一分钟，与上一实际交易日同一分钟比较，显示差额（亿元）和百分比。涨跌用正负号表示。午休显示上午收盘值，收盘和周末显示最近交易日的数据及日期。上一交易日数据缺失时只显示已核实的本日金额。

上证指数和科创50各自按北京时间的五分钟 K 线判断放量。盘中每 20 秒取指数快照，用日内累计成交额减去此前已收盘各根的成交额，并与当根 K 线的金额和价格交叉核对。报价尚未对齐时，使用同源分时行情的成交额、价格和时间。历史同刻基线优先取东方财富，缺失时使用新浪历史五分钟线。

| 指数 | 一重 | 下一根二重确认 | 最低五分钟成交额 |
| --- | ---: | ---: | ---: |
| 上证指数 | 1.8 倍 | 1.5 倍 | 150 亿元 |
| 科创50 | 2.0 倍 | 1.6 倍 | 20 亿元 |

上午和下午各自的前五根 K 线用此前 20 个完整交易日同一根的成交额中位数作基线。之后取本时段此前五根完整 K 线，去掉最高和最低，再取平均。实际成交额已达倍数和金额双门槛时可立即触发。否则等满 60 秒，按已过秒数线性折算到五分钟。价格需不低于本根开盘价且位于区间上半部，或较前一根收盘价跌幅在 0.15% 以内且位于区间 65% 以上。

一重触发时冻结基线。紧接着的下一根内持续检查二重条件，确认窗口随该根结束，午休、隔夜或跳过该根都使窗口失效。每根只弹一次，提醒记录随监控进度保存，重启可继续确认。弹窗列出指数、当根实际金额、等效金额和基线倍数。

运行 `python -m unittest discover -s apps/nga-watcher -v` 验证监控。运行 `python apps/nga-watcher/watcher.py --smoke-test` 检查窗口，测试期间无声并自动退出。

空楼层的校验规则及实际恢复结果见 [2026-11-05 修复记录](验证记录-20261105-空楼层修复.md)。
